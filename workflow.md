# Production playbook

## Розбір відео перед промптом

1. **Імпорт.** Записати джерело, права, SHA-256, fps/VFR, timebase, тривалість, колірний простір, канали аудіо. Оригінал зберігати окремо. Для перегляду зробити проксі з тією ж часовою віссю; для монтажу VFR перевести у CFR, задокументувати відповідність часу. HDR перевіряти на HDR-дисплеї або використовувати визначений SDR-тонмап для preview.
2. **Збір доказів.** Зробити ASR зі словами, таймкодами та, якщо можливо, мітками мовців. Із відео витягнути межі сцен та contact sheet, густіше на швидких рухах, репліках та UI-переходах. Для назв, екранів і титрів додати OCR. За потреби переглянути синхронізовані фрагменти в реальному часі зі звуком. Провайдери video understanding можуть семплювати кадри й пропускати короткі події; важливі інтервали перевіряти локально. [Gemini video understanding](https://ai.google.dev/gemini-api/docs/video-understanding) · [PySceneDetect](https://www.scenedetect.com/) · [whisper.cpp](https://github.com/ggml-org/whisper.cpp)
3. **Перший прохід.** Попросити покадрово прив'язаний shot log: `source_id, in_ms, out_ms, quote, on_screen_text, visual_action, camera, speaker, audio_event, tags, evidence_frames, uncertainty`. Для довгого матеріалу використовувати перекривні фрагменти з абсолютним offset; дедуплікувати за первинним джерелом і часом. Де модель не бачить факту, залишати null. 
4. **Другий прохід.** Попросити 3–5 історій з гачком, розвитком і завершенням, ранжувати за самодостатністю, ясністю, енергією, візуальною відмінністю та можливістю кадрування. До кожного cut додається причина й 0,25–0,5 с монтажного запасу за наявності. Для реакцій позначати точну репліку, затримку, джерело реакції, пріоритет звуку та чи потрібен split-screen.
5. **Промпт для виробництва.** Передати лише погоджений уривок/референс, ціль кадру, об'єкт, дію, композицію, рух камери, світло, тривалість, формат, початок/кінець та обмеження безперервності. Промпт для редагування описує, що змінити та які конкретні властивості зберегти. Якщо потрібен точний титр, додати його через HTML/Remotion/Fusion після генерації. Архівувати prompt, endpoint, inputs, seed за підтримки, вартість, ID і результат.
6. **Збірка.** Маніфест має містити `assets`, `edits`, `captions`, `audio`, `overlays`, `output_profiles` та producer/version for generated media. Джерело задавати PTS/мілісекундами або раціональним timecode, вихід — кадрами з правилом округлення. Обробляти діапазони як [in, out). Публікувати MP4, sidecar SRT/VTT, review MP4 з таймкодом і за потреби NLE handoff. Для NLE перевіряти round-trip через OTIO/XML/AAF/EDL на цільовій версії, особливо retime, effects, transitions, multicam і кадрування. [OpenTimelineIO](https://opentimelineio.readthedocs.io/)
7. **Review.** Переглянути весь експорт зі звуком, перевірити перший і останній кадр, межі переходів, огріхи ASR і всі місця синтетичної заміни. Додатково кадри з найбільшими титрами, mobile safe zones, чорні/повторні кадри, peaks, loudness, HDR/SDR, відсутні шрифти, lipsync, міміку, логотипи. Прив'язати відгук до версії й timecode. Погоджені детерміновані кадри й ASR повторно використовувати за хешем.

### Пілот Outspoken

Файл `r14/launch-16x9-final-a.mp4`: 40 с, [метадані](reference/outspoken-metadata.json), [контактний аркуш](reference/outspoken-contact.jpg). Візуальний семпл кожні 3 с показав dark/light систему, логотип із золотим акцентом, діагональний wipe, секції repository / tools / research / results і картки метрик. На зменшеному прев'ю найбільш дрібні списки навантажені; для вертикальної версії переверстати на одну тезу й один масштабний доказ на сцену. Контраст титрів перевіряти на обох фонах. Integrated audio −19,2 LUFS, LRA 4,8 LU; ціль гучності вибирати за каналом і контролювати true peak. Семплінг і вимірювання не покривають суцільний audio-visual перегляд або точність діалогу.

Логотип, ціна й CTA — окремі шари. |

| Data/explainer | Сценарій → запис голосу → розкладка на смислові блоки → графіки з даних → анімація й субтитри | Компонент із даними на вхід, масштабувати на інші цифри й мови. Звірити числа, шкалу, джерела й час читання. |

### Оптимізація HTML + готове відео

- Без графіки та фільтрів FFmpeg `-c copy` дає дешевий проксі/грубий cut біля ключового кадру. Для точних меж декодувати потрібні діапазони й кодувати цільовий монтаж. За кількох форматів брати ті самі джерела й рішення монтажу, а кадрування задавати окремо.
- Рендерити весь таймлайн в HTML, коли компонування щільно пов'язане з медіа. Інакше рендерити виключно титри, transitions і акценти на прозорому фоні. Зводити їх з оригіналом у FFmpeg/Resolve. Для NLE перевірити ProRes 4444 або PNG sequence; для WebM перевірити декодування alpha у цільовому інструменті. Перевіряти premultiplied/straight alpha.
- Прив'язати стан до номера кадру або seek(t), зафіксувати seed, шрифти, браузер і версії. Анімації за wall clock, dynamic network requests і випадковий runtime seed роблять кадри нестабільними. Збирати source footage, proxy, transcript, captions і overlays в окремих кешах. Почати з 2–4 browser workers та порівняти RAM, temp cache, час і результати перед збільшенням. Тримати важкі frame cache і проксі на SSD достатнього обсягу.
- За багаторазового прогону використовувати low-res preview, stills ключових кадрів і re-render окремих сцен. Фінальні елементи лише один раз кодувати під delivery; проміжний mezzanine використовувати коли необхідно.

## Послідовність впровадження

1. Взяти approved reference або той самий Outspoken, прогнати FFmpeg → shot log → короткий clip → субтитри → локальний HyperFrames overlay → FFmpeg delivery. Взяти шаблони з наявного Outspoken після звірки з джерелом.
2. Підключити локальний ASR у власний runtime та перевірити українську, англійську й перемикання мови на відомій репліці. Швидко порівняти whisper.cpp і доступні cloud ASR після відновлення балансу та погодження матеріалів.
3. Порівняти HyperFrames і Remotion на однаковій 10-секундній сцені. Метрики — cold/warm render, failed frames, пік RAM/SSD, читабельність, трудовитрати одного edit і експорт 2–3 форматів.
4. Після відновлення доступу до NLE перевірити один synthetic rough cut, import/export, subtitles і зовнішній review. Після відновлення fal прогнати короткий B-roll, один edit і один dubbing test, визначити допустимий бюджет на погоджений кадр та повтори.
